# 开发视角审查 `dev_review`

必须由一个全新的独立审查 agent 执行。审查者假定此前完全不知道该事项，只按当前输入材料首次阅读；不得读取完整对话、作者意图、历史讨论或其他审查结果。审查实现边界、数据来源、接口依赖、权限模型、异常路径、历史数据和工程歧义。不要编写技术方案或代码，不要修改需求正文。

输入当前文档或技术相关片段、最小必要的已知系统约束和审查目标。返回实现歧义、风险、缺失决策和待确认问题；每项注明证据位置、影响范围、是否阻断开发以及建议澄清方式。

同时返回问题台账：问题编号、首次提出的阅读位置/阶段、证据、问题、影响、建议、状态（`UNRESOLVED`、`ANSWERED_LATER`、`PARTIALLY_ANSWERED` 或 `CONFLICTING_ANSWER`）和后文解答证据。后文已解答的问题也必须保留，供主会话在对话中列出；不得写入需求文档。
