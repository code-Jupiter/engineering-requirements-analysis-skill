# 需求变更差异审查包 `diff_review_pack`

本能力只服务于“已有需求说明书变更工作流”的文档修改之后、最终交付之前。必须由一个全新的独立审查 agent 执行；审查者假定此前完全不知道该事项，只按当前输入材料首次阅读，不读取完整对话、作者意图、历史讨论或其他审查结果。对比修改前后的需求说明书，并以已确认的影响面矩阵为依据审查实际差异。不要继续修改文档，不要把潜在问题直接改写成已确认需求。

输入修改前文档、修改后文档、已确认的影响面矩阵、用户确认结果和最小必要事实。

输出差异审查包，必须说明：

1. 实际修改了哪些章节；
2. 每个章节具体修改了什么；
3. 需求清单是否已同步；
4. 哪些章节检查后无需修改；
5. 是否覆盖或冲突了旧规则；
6. 用户需要人工重点检查的 3–5 个地方。

同时标记影响面矩阵中计划修改但实际未修改的内容、超出矩阵的修改、潜在冲突和交付阻断项。只有差异审查包没有未决阻断项，或用户明确接受这些事项后，才能交付最终文档。

维护问题台账：问题编号、首次提出的对比位置/阶段、证据、问题、影响、建议、状态（`UNRESOLVED`、`ANSWERED_LATER`、`PARTIALLY_ANSWERED` 或 `CONFLICTING_ANSWER`）和解答证据。后续被修改内容或另一处证据解答的问题也必须保留，并由主会话在对话中列出；问题和建议不得写入修改后文档。
