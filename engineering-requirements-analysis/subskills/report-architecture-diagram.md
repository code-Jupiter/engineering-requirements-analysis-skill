# 汇报架构图 `report_architecture_diagram`

目标是单页 16:9 汇报表达，不是脑图、业务流程图或全量技术依赖图。输入业务内容、来源证据、听众和必须保留关系。

先分类为左栏用途（汇总、对比、稽核）、中栏来源系统与数据项、右栏结果（提醒、生成、审批、推送、展示）。语义合并相近内容，记录合并与省略理由，确认关键关系取舍后再出图；不得删除用户指定必须保留的关系或改写来源事实。

默认模板为横向三栏、蓝色系、正式风格、对齐与留白；用户指定其他模板时遵循其选择。中栏每个系统一个容器，内部横向数据条上下排列；左右栏模块收敛、名称简短。整图控制在单页视觉范围内。

数据项直接连接用途或结果，避免装饰性汇聚节点、长竖向总线和密集交叉。通过调整上下顺序减少交叉，优先短直线、水平线和轻微折线。每个模块默认只表达最关键的 1–3 条关系；关系太多时简化展示而非改动业务事实。若必须保留的关系无法清晰容纳，说明冲突并请求拆页/换版式，不擅自删除。

按 `references/diagram-delivery.md` 交付可编辑文件；输出简化/省略关系清单，并标明“汇报简化视图，不用于全量依赖验收”。
