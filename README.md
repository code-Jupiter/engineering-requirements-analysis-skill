中文工程需求与业务汇报共创 skill。保留需求文档梳理和已有文档变更两条核心工作流，增加业务流程图、演示场景探索、叙事大纲、汇报架构图和演示制品验收。

## 目录与安装

`engineering-requirements-analysis/` 是完整 skill，包含入口、内部能力、参考规则和显式调用元数据。复制该文件夹至使用环境的 skills 目录，或用支持仓库子目录的技能安装器安装；本仓库不附带项目文件、个人配置、业务样例或会话记录。安装目录取决于使用环境，不在 skill 中硬编码。

调用：`$engineering-requirements-analysis`。默认中文，必须用户点名；输出方案确认后才执行。安装此发布版时注意与同名本地版本冲突，先备份并自行选择替换，不同时安装两个同名版本。

## 支持场景

| 目标                   | 交付                                           |
| ---------------------- | ---------------------------------------------- |
| 零散材料形成需求说明书 | 完整性检查、模块描述确认、初稿、独立审查、终稿 |
| 已有需求说明书变更     | 影响面矩阵、确认后最小修改、差异审查包         |
| 业务流程图             | 流程理解、确认后可编辑 Excalidraw 图           |
| PPT 目标探索           | 叙事路线、低成本验证、反馈状态继承             |
| PPT 结构规划           | 思路确认稿、确认后规定格式大纲 JSON            |
| 单页汇报架构图         | 16:9 三栏简化视图、省略关系说明                |
| 演示制作               | 经确认的 HTML/PPTX 等制品、逐页真实检查        |

示例请求：

> 使用 $engineering-requirements-analysis。目标读者为业务侧客户，基于我提供的会议纪要梳理需求说明书。输出 Markdown，重点检查角色、流程、口径、异常和验收。先展示方案，不直接生成终稿。

> 使用 $engineering-requirements-analysis。只做 PPT 演示思路确认稿，听众为项目决策者，时长十分钟。不要输出最终大纲 JSON，也不要制作页面。

## 环境依赖与限制

- 独立审查需要运行环境支持独立子智能体。不可用时说明阻断，不以主会话审查冒充盲审。
- 委托模型按用户指令、特殊内容规则、会话初始配置解析；配置不可读取或模型不可用时请求用户决定，不静默替换。文中的模型名称只是用户指令示例，不是平台通用可用性承诺。
- Excalidraw 实际打开、HTML/PPTX 逐页渲染以及字体检查需要相应工具。skill 提供流程和规则，不捆绑编辑器、字体或导出引擎。
- 工作区、目标读者和格式是任务参数；不自动切换目录、不上传、不公开业务材料。
- 当前检查为文本结构和发布包检查，尚未通过全部工作流的端到端运行测试；见 `VALIDATION.md`。
